CLOVER: Continuous Learning Over Agent Trajectories

A continual-learning overseer that decides what to learn from production agent traffic, verifies it, and decides where it belongs: in one user's memory, in a skill shared across users, or in the weights.

Romil Shah · November 2026

Abstract

A deployed agent produces far more experience than anyone can learn from, and retraining is slow, expensive, global, and hard to reverse. Two decisions gate any continual-learning loop, and both are usually made by hand. Attribution decides which traces, and which step in a trace, carry signal. Placement decides whether a learning belongs in context or memory, in a cross-user representation, or in the weights.

CLOVER automates both. It has three operators, attribute → consolidate → integrate, and is grounded in Complementary Learning Systems: fast per-user memory, slower cross-user skills, then consolidation into parametric weights. Every step verdict is tied to an independent verifier rather than an LLM's opinion. Every cross-user learning must show transfer lift on held-out users who never produced it, and must pass human review. We also introduce CLBench, a multi-tenant continual-learning benchmark. In internal evaluation and a production agentic-search launch, each added scope (user, then cross-user, then weights) improved continual-learning gain while forgetting stayed bounded.

01 · MOTIVATIONThe lesson that never travels

Every deployed model generates more experience than you can learn from. The question is what to learn from, and where to put what you learn.

Today's methods each cover a single level of the problem. Conversation memory stores one user's facts. Skill banks share procedures across users. Preference optimization and rejection-sampling distillation change the weights. None of them couples the levels, so a lesson one user's session earns rarely reaches the next user, and almost never reaches the model.

Continual learning needs updates at all three levels, connected by causal attribution and verified admission:

  • User-specific: this user's facts, preferences, and episodes. Fast and reversible.
  • Cross-user: patterns shared across users, such as skills, vocabulary, and procedures.
  • Model: durable capability baked into the weights. Slow and consolidated.

03 · SYSTEMThree operators

CLOVER runs as two agents and an integration layer. The attribution agent locates signal. The consolidation agent proposes, verifies, and organizes learnings. Integration enacts them, first at test time and later in the weights. Logged outcomes feed the next attribution cycle, which closes the flywheel.

The formulation

Notation: τ is a trajectory, o(τ) its outcome, M the typed memory, θ the weights, u the user context, and Rℓ the passing rubric attached to a learning ℓ.

① Attribution: pivotal steps, rubrics, hooks (S*, R, H) = A(τ, o(τ), M) S* ⊆ steps(τ) vᵢ = verify_indep(sᵢ), vᵢ ∈ {right, wrong, unknown} ② Consolidation: propose, then verify ℓ = L(τ, S*, H) typed learning from pivotal steps admit(ℓ) = V(ℓ; R) ∧ human general + attribution rubric; hard-reject M ← M ∪ { ℓ : admit(ℓ) = 1 } into user / cross-user / model store ③ Integration: fast arm, then slow arm π′(a | s, u) = π_θ(a | s, retrieve(M, u)) test-time injection θ′ = argmin_θ 𝔼_D[ℒ(θ)], D = hint-fuse({ℓ : admit}) hints → weights

A learning is first used through injection (π′). Only after that does it graduate into the weights (θ′). This is the fast-to-slow migration that Complementary Learning Systems describes, with hippocampal recall first and neocortical consolidation second.

04 · PILLAR IAttribution: grounded verdicts, recall-first

The proposer proposes and the verifier disposes. Each step gets a verdict vi ∈ {right, wrong, unknown}, a confidence, and a passing rubric Rℓ. A verdict is only as trustworthy as the verifier behind it, so the verifiers are ranked by how well grounded they are:

VerifierChecksTrust tier
Execution / tool successEnvironment ground truthHighest
Groundedness / citationClaim ↔ retrieved evidenceHigh to medium
Constraint / schema / formatWhether a parseable rule is satisfiedHigh, narrow
Contradiction / consistencyConflicts with earlier stepsMedium
Distance-to-goal / graphWhether the step reduces graph distanceMedium
LLM-as-judgeAn opinionPropose-only
Worked example: a deep-research agent hallucinates a claim. Detect: the groundedness check fires. Localize: it points to the step that asserts a claim without tool support. Necessity: when that assertion is neutralized, the hallucination clears. Emit: the guardrail "verify each claim before asserting", with rubric Rℓ: the ungrounded-claim rate goes down.

05 · PILLAR IIConsolidation: propose, verify, organize

Propose: learnings are inferred across trajectories

A cross-user skill is not written by any single session. It is discovered when the same fragment shows up across several users. Every attributed pivotal step is written to a skill-fragment index, embedded by its hook and environment signature, along with its outcome, scope (user, tenant, or cluster), and provenance. Offline, fragments are clustered and mined with PrefixSpan, using a minimum support counted in distinct users. A candidate is proposed only if it clears the propose-gate: ≥k Sybil-checked users, ≥d task clusters, it can be abstracted, and its type is one of vocabulary, skill, or procedure.

User A: "compare H100 cloud prices" s1 search("H100 cloud price 2026") s2 open(blog "cheapest GPU clouds") s3 extract price ⚠ dated 2024 s4 ★ open(vendor live calculator) → current price s5 cite primary source ✓ hook: verify-freshness-before-cite ★ = pivotal step

The index record keeps the signature search→open(3p)→extract→detect-stale→open(primary)→extract with env-sig {task: price-lookup, error: stale-source}. User B (flight fares, where "the fare shown was cached") and User C (drug prices, "list price vs. live pharmacy") hit the same fragment on unrelated topics. Lifted, it becomes a cross-user skill:

Prefer the primary source for time-sensitive facts. For facts that change, such as prices, availability, and rankings, prefer the live or primary source over a cached third-party copy. (1) Flag time-sensitive facts. (2) Check when the source was last updated. (3) If it is stale or third-party, open the primary source. (4) Cite the primary source.

Verify: one general rubric plus Rℓ, hard-reject

Each candidate must be measurable, beneficial, and safe to share. The decisive cross-user test is transfer lift on held-out users who never generated the learning. Human review is mandatory for cross-user and model-scope admissions. The review budget only orders the queue and can never bypass it. In the example, the skill is measured by the freshness-error rate on held-out research tasks, shows lift on users who did not generate it, and is abstracted with no PII before sign-off.

Organize: route by type and lifecycle

  • Encoding: a fast write to the right store (user memory, shared memory, or the finetuning dataset).
  • Schema integration: merge into an existing shared skill or vocabulary entry. In the example, the new skill merges with the citation-hygiene skills.
  • Reconsolidation: offline re-read, revise, and re-stabilize, with every version kept.
  • Decay and GC: Ebbinghaus-style decay of unused entries and utility-based eviction.
  • Conflict resolution: by recency, source trust, and support.

06 · PILLAR IIIIntegration: the two arms of CLS

Consolidation selects and files learnings. Integration enacts them.

Test-time injection: fast, reversible, per-request

Scope and ABAC filtering come first, pushed down into the retrieval predicate. Ranking is similarity × trust with a deliberately low k. A learned "when-to-apply" gate decides whether to use a retrieved skill, so retrieval never forces its use. Skills are surfaced by progressive disclosure. Each outcome is logged and feeds the next attribution cycle.

Finetuning: slow, systems consolidation, semi-permanent

Admitted learnings are fused into a dataset and trained with SFT plus on-policy self-distillation (OPSD), which limits forgetting. The model then passes an eval gate and a mandatory human sign-off before deployment, with versioned rollback if the holdback set regresses. This step applies the same Verify discipline at model scope.

07 · EVALUATIONCLBench: measuring system-level learning

No existing benchmark tests continual learning across tenants, so we built one. CLBench streams tasks from many simulated users with planted scope labels and measures:

  • CLG, Continual-Learning Gain (primary): cumulative task-success lift across the stream, compared with a no-memory baseline, reported net of forgetting.
  • XTL, Cross-user Transfer Lift: the zero-shot lift for a held-out user from learnings they never generated.
  • SRF, Scope-Routing F1: whether admitted learnings land at the planted scope.
  • Forgetting rate (counter-metric): regression on tasks the system had already solved. It must stay near zero.
  • LoCoMo success lift (public benchmark): success rate with the CLOVER loop on versus off.

Three findings hold across the ablation. Each added scope adds gain: user memory, then cross-user skills, then weights, each improve CLG and LoCoMo monotonically. Cross-user transfer comes only from consolidation: per-user memory gives a new user essentially nothing, while verified cross-user skills give clear lift that grows after finetuning. Forgetting stays bounded: it is low and roughly level across every memory configuration, including after weight updates.

09 · LIMITATIONSLimitations and future work

Limitations

  • Replay validity: the environment can change between the original trace and its replay. This is the largest remaining risk.
  • Breadth of the flywheel-to-weights path: it has been shown for personalized research and is unproven beyond it.
  • Fragment grouping across trajectories is LLM-based and low precision.
  • The no-ground-truth long tail cannot be promoted. This is a stated bound of the system, not an oversight.

Future work

  • Parametric and architectural memory: an adaptable weight-layer substrate for vocabulary, skills, and alignment that stays private and revocable.
  • Shared cross-user preference defaults, with consent and opt-in.
  • Grouping fragments by behavioral equivalence instead of LLM judgment.
  • Calibrating k and d against CLBench's scope labels.

The weight layer is the bottleneck. The next step is to make the substrate itself adaptable.

That is the thesis of the continual learning landscape note: the production stack has context, a non-parametric store, and consolidated weights, with a gap where adaptable, governable parametric memory belongs.
