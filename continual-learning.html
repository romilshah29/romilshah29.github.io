The continual learning landscape

Current systems rely on agentic memory and data flywheels. Both leave the model's weights frozen between releases. Parametric memory is the next front.

Romil Shah · October 2026

A deployed model is frozen at its weights. Everything we call continual learning today is built to work around that frozen core, not to move it. Production systems put all the adaptation in a non-parametric layer: agentic memory at serve time, and a data flywheel that retrains offline. Both are real and both work. Both leave the weights static between releases. The next front is parametric memory, where the model updates its own weights continuously, and the 2026 research has moved decisively in that direction.

The three places adaptation can live

Every continual-learning method puts the update in one of three substrates. This is the organizing axis across the recent agent-memory surveys.

  1. Context. Information lives in the prompt or KV cache. No parameters change, so no catastrophic forgetting, but it is ephemeral and bounded by the window.
  2. Non-parametric memory. Retrieval, RAG, agentic memory. The backbone stays frozen; an external store holds and serves knowledge. Inspectable and governable, but the model itself does not learn. The store grows; the weights do not.
  3. Parametric memory. The update lands in the parameters. Seamless at read time, the model just knows the thing, but writes are costly and risk interference and forgetting.

A system whose memory only grows is accumulating. A system whose memory consolidates, forgets, and reshapes itself is learning.

By that definition, most of what ships today is accumulation.

Where production is now

Agentic memory — serve-time, non-parametric

The deployed state of the art. Memory operations, what to write, what to retrieve, what to compress, are handled by an explicit read-write store around a frozen model. The recent work makes those operations themselves learned, training memory ops as reinforcement-learning actions that beat prior memory-augmented baselines. But the backbone is still frozen. The intelligence is in the policy over the store, not in the model's weights. Production favors this for a concrete reason: inspectability and governance. A non-parametric store can be audited, a row can be deleted, provenance is preserved, a stale fact can be excised.

Data flywheel — offline, parametric but batched

The other half of the stack. Production signal to preference data to the next post-training run. This does update weights, but discretely, offline, at release cadence, not continuously and not at test time. It is consolidation on a slow clock. The model between releases is still frozen; the flywheel just makes the next frozen checkpoint better.

The honest limitation of both

Agentic memory keeps the model static and is bolted on: the agent sometimes ignores retrieved records or uses them inconsistently, because retrieval is not the same as knowing. The data flywheel has release latency baked in: nothing the model learns from an interaction reaches its weights until the next training cycle. Put together, today's continual learning is a frozen core plus an external scaffold plus a slow offline retrain. The weights do not move in real time. That is the gap.

The next front: parametric memory

The research front has moved to making the weights themselves the adaptive substrate, continuously and at test time. The unifying idea is to reframe adaptation as updating parameters during inference rather than storing text beside a frozen model.

Test-time training — the core mechanism

Weights update during inference using a self-supervised loss, compressing context directly into parameters rather than caching it. The Stanford and Nvidia TTT-E2E work frames long-context modeling as a continual-learning problem: the model updates dynamic MLP weights during inference via next-token loss, and meta-learns an initialization that is easy to update at test time. It matches full-attention accuracy at long context with linear-model speed. The architecture is explicitly dual-memory: sliding-window attention as working memory, immutable MLPs preserving pretrained knowledge, and dynamic MLPs as the learned long-term store. A parallel line endows existing models with in-place test-time training, treating any parameters as fast weights in an apply-then-update cycle.

Parameterizing experience — memory that becomes weights

The agent-memory line is pushing the store into the parameters. One approach converts retrieval memory into parameter-resident skills via isolated mixture-of-experts LoRA adapters, with a failure-as-training-signal loop that promotes successful patterns into weights. Another uses reflection-driven test-time training on episode-local adapters, keeping the backbone frozen and updating only lightweight fast weights from constructed and revised lessons. A third makes the parametric state recurrent and constant-size, distilling a full-history teacher into a bounded recurrent memory rather than an unbounded store.

Gradient-free adaptation — the efficiency wing

Not all of the front requires backprop at serve time. Some methods do test-time policy improvement by modulating output logits in closed form from a non-parametric experience memory, with no gradient updates at all. Same destination, adapt after deployment, by a cheaper route. This is the wing the efficiency-first labs are betting on.

Why parametric is the front, and why it is hard

Parametric memory is the only one of the three substrates where the model actually learns rather than consults. It offers seamless integration, long-term consolidation, and bounded, constant-size state instead of an ever-growing store. That is why the research has moved there. The reason it is a front and not yet the default is a set of hard problems that make up the real agenda:

  • Catastrophic forgetting. Writing new knowledge to weights degrades old. The classic mitigations do not scale cleanly to frontier models, and even synthetic-data finetuning induces forgetting on real and out-of-distribution data at production scale.
  • No tombstone. Parametric memory has no delete. A fact cannot be excised from a weight matrix the way a row is dropped from a store, and you cannot attribute a behavior to the specific update that caused it and revert just that update. This is the governance wall, and it is why inspectable non-parametric stores still win in production.
  • Write cost and stability. Updates are expensive and must avoid interference. Recurrent compression makes the state bounded but irreversible: once folded in, an observation cannot be recovered or removed.
  • Rate heterogeneity. Different knowledge changes at different rates, yet a single update mechanism treats all evidence as equally worth absorbing. The multi-timescale framing, fast fading and slow consolidating, is the response.
  • Evaluation gap. Nobody evaluates forgetting well. Few benchmarks test selective forgetting explicitly, so the field cannot yet measure the thing parametric memory most needs to get right.

The synthesis

The trajectory is a continuum of plasticity across timescales, not a winner among the three substrates. Context is working memory, per-interaction and ephemeral. The non-parametric store is fast, inspectable, and governable, the serve-time layer. Parametric fast weights are within-session learning that compresses experience into bounded weight state, the new middle layer. Consolidated base weights are slow and release-cadence, the data flywheel's output.

Today's production stack has the first, second, and fourth, with a hard gap where the third belongs. Parametric memory is the research front precisely because it fills that gap: it makes the serve-time layer learn instead of merely store, and it gives the consolidation loop a fast-clock counterpart. The open problem that gates it is governance, a parametric substrate with a delete, attributable updates, reversible writes, and forgetting that is selective by design rather than catastrophic by accident.
